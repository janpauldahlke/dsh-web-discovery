# P_03 — Contract v1 + heuristic categorizer

**Why:** the receipt becomes a public API (future web-search replacement). Freeze it here, once.

## Steps

1. **Contract input:** collect the DSH built-in web-search tool's name, args and result shape (NEXT.md item). Design v1 so it is a **superset**, so P_07 is an alias rather than a migration.
2. **Types:** `DiscoveryReceiptV1` in `src/shared/types.ts`; `v: 1`; closed `flags` and `label` enums; fixed error-code prefixes.
3. **Engine registry cleanup:** one `EngineSpec { kind, configKey, envKey, create }` list. Config and presence are derived from it, which removes the hand-written per-engine branches in `config.ts` / `discovery-tool.ts`.
4. **`Categorizer` interface:** `categorize(query, rows) → { labels, flags, order }`. The `heuristic` impl does:
   - host extraction, dup host, login/paywall cues, docs/official cues (`docs.`, `/docs/`, `developer.`, `.org` priors, GitHub repos);
   - token miss on title+snippet;
   - operator `denylist` (dropped, counted) and `priors` (boost).
5. **Receipt size guard:** truncate snippets; hard cap ~1.5k tokens (estimate as chars ÷ 4).
6. **Smoke:** golden fixtures (from P_02) → expected labels and order. This is the regression net for any heuristic tweak.

## Acceptance

- Every row has `label`; the receipt carries `v: 1`; the size guard is tested; `npm test` green.
- Missions reads v1 with no change (or a one-line one).

## Trap

Do **not** grow the heuristics into a giant host list. Priors and denylist are operator config, not code.
