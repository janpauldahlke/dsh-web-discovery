# P_02 — browser39 first-class + the upstream case

**Stance:** we assume **no** upstream change. We ship the best adapter today's CLI allows, and we gather evidence so Alejandro *wants* the improvement.

## Steps

1. **Capability audit (written down here):** `browser39 --help`, `search --help`, `fetch --help`, version. Questions to answer:
   - backends;
   - result count;
   - timeouts;
   - is there snippet text in `markdown` that we currently ignore?
2. **Fixtures corpus:** capture ~15 real `search --output json` replies covering docs, news, a German query, an obscure query and a blocked reply. Store them in `scripts/fixtures/browser39/` and use them in the smoke test.
3. **Mapping upgrade (deterministic, no HTML scrape):**
   - pair each SERP link with the text near it in the CLI's `markdown`, if any, to get a snippet;
   - stay inside the Eris rule: read only the CLI's structured fields;
   - **no** separate DDG HTML request.
4. **Order + budget:**
   - `DISCOVERY_ENGINES = ['browser39','searxng']`;
   - `maxDiscoveryMs` 45 s total, browser39 ≤ 25 s;
   - `budget_exhausted` error code.
5. **Measurement script** (`scripts/measure-browser39.mjs`, manual, not in `npm test`): N queries → block rate, p50/p90 latency, links per reply, junk ratio.
6. **Evidence pack for Alejandro** (`agent/upstream/browser39-proposal.md`):
   - the problem;
   - our measurements;
   - the proposed `search --output json` result schema `{results:[{url,title,snippet}]}` and a `--backend` flag;
   - sample fixtures;
   - an offer to write the PR.

   Send it only once the numbers exist.

## Acceptance

- Auto order flipped; a blocked reply falls through to SearXNG within the budget (stub test).
- Snippet yield measured; mapped if it's present.
- Proposal drafted with real numbers.

## Kill/trigger

If the block rate is above 30% or p50 is above 20 s, raise it at P_06 (the browser39 lock gets revisited).
