# P_04 — LLM categorizer (opt-in)

**Off the critical path.** Build it only once P_03's heuristic labels exist, so we have something to compare against.

## Steps

1. **Config:** `categorizerEndpoint` (empty = off), `categorizerModel`, `categorizerApiKeyEnv`, `categorizerTimeoutMs` (default 5000).
2. **Client:** OpenAI-compatible `/v1/chat/completions`, temperature 0, JSON-schema response, closed label set. Input: query + ≤ 8 rows. Output: `[{i,label}]`. No query rewrite, no fetch, no loop.
3. **Merge:** LLM labels override heuristic labels; flags stay from heuristic. Any failure → `heuristic (llm unavailable)`.
4. **Labelling:** a localhost endpoint is `llm-local`, anything else is `llm-remote`. README warns that remote breaks local-first / ISO.
5. **Local recipe (docs only):** a 1–2B Q4 model on llama.cpp **on CPU**, on its own port (not `:8080`). Measure latency on the box while the 27B model is running.
6. **Smoke:** stub HTTP server covering good JSON, bad JSON and timeout.
7. **A/B switch:** a config flag so P_06 can compare.

## Acceptance

- Off by default; failures never fail the search; adds ≤ 5 s p90 on the operator box (measured).

## Kill

See P_00 §9: under ~15% gain or more than 5 s added → remove.
