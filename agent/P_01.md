# P_01 — Live wire + strict skill + logging

**Why first:** this is the cheapest step with the most value. Real URLs reach the agent today, even without any ranking.
**Repos:** this one + `dsh-web-missions` (skill, health).

## Steps

1. **Profile wire:** point `~/.dsh/profiles/web/node_modules/dsh-web-discovery` at this checkout; remove the stale `dsh-local-web-discovery` link; check that the Loader picks up the bundle patch.
2. **Pick a live engine:** browser39 on PATH (today's adapter as-is). SearXNG is optional here.
3. **Boot `:3090`.** Check:
   - the tool list shows `discovery_search`;
   - `/health` reports `discovery: "on"`;
   - a search with `mission_id` writes `discovery.json`, and `mission_status` shows it.
4. **Skill (missions `web-mission-workflow`):**
   - when discovery is present, **never invent or recall URLs**;
   - build the query from the mission Goal;
   - one search, then fetch the top 1–2 rows; on 404/thin, take the next row;
   - `no_engine` → ask the user.
5. **Provenance log (data for the metric):** missions marks each fetched URL as `discovery | user | other`, compared against `discovery.json` and the prompt. **Log only; don't block** (see CRITIQUE C1).
6. **Per-mission summary line:** used / exists / useful, so P_06 can be counted instead of guessed.
7. **`limit` default 10 → 5** (one-line change, do it now).

## Acceptance

- The three live checks in step 3 pass.
- 3 real missions run end to end, and the provenance log shows mostly `discovery` URLs.
- `npm test` is green in both repos.
